# 标准动作单独展示优化详细计划

## 1. 背景

当前舞蹈跟练体验的主要矛盾是：用户实时画面、用户骨架、标准动作骨架、评分 HUD 同时叠在一个舞台里，用户需要在杂乱画面中找标准动作，跟练注意力被明显分散。

本方案围绕三个核心目标推进：

1. 界面简洁：隐藏用户实时画面和用户骨架，只保留标准教学动作。
2. 视觉清晰：根据用户衣着主色自动生成高对比教师线条色，提升辨识度。
3. 动作真实：从直线骨架升级为更接近人体肌肉和 BJD 关节质感的标准动作模型。

## 2. 目标与非目标

### 2.1 目标

- 练习页视觉层只显示标准动作，不显示摄像头画面和用户动作线条。
- 摄像头仍然打开，继续用于 MediaPipe 姿态识别、动作比对、实时评分和结果结算。
- 评分 HUD 固定保留，用户可以同时看到标准动作和匹配分数。
- 标准动作颜色根据用户衣着主色动态生成互补/对比色。
- 标准动作人体轮廓从机械直线升级为曲线躯干、渐变四肢、关节球的模型。
- 旧入口 `pose_viewer.html` 与新入口 `web/` 保持行为一致。

### 2.2 非目标

- 不在本阶段替换 MediaPipe 模型。
- 不改变现有评分算法的核心计算逻辑。
- 不引入账号、云端存储、动作库后端化。
- 不直接搭建 Remotion 项目；仅预留后续用于演示视频/对比视频生成的验收点。

## 3. 用户体验设计

### 3.1 练习页显示逻辑

练习页分为三层：

| 层级 | 显示内容 | 说明 |
| --- | --- | --- |
| 输入层 | 隐藏的 `#cameraVideo` | 只给 MediaPipe 使用，不参与视觉展示 |
| 教学层 | 标准动作人体模型 + 标准手部线条 | 舞台唯一动作主体 |
| 反馈层 | 分数环、当前总分、节拍提示、状态提示 | 固定位置展示，不遮挡主体动作 |

用户看到的是：

- 深色沉浸舞台背景。
- 居中标准动作模型。
- 左上/底部评分反馈。
- 摄像头授权或人体识别状态提示。

用户看不到的是：

- 用户自己的摄像头画面。
- 用户自己的实时骨架。
- 用户手部识别线条。

### 3.2 评分保留机制

隐藏用户画面不等于取消识别。识别链路保持原样：

1. `cameraVideo` 持续接收摄像头流。
2. MediaPipe Pose/Hands 继续读取 video frame。
3. `state.lastPose` 和 `state.lastHands` 继续更新。
4. `safeRefreshMatchScore()` 继续执行动作比对。
5. `renderPracticeView()` 继续刷新分数环、总分、左右臂摘要。

视觉层只是不再调用用户骨架绘制函数。

## 4. 技术方案

### 4.1 旧入口改造范围

文件：`pose_viewer.html`

需要改造的模块：

- CSS 舞台背景与 `#cameraVideo` 隐藏。
- 颜色采样与互补色计算工具函数。
- 标准动作渲染分支。
- 人体模型绘制函数。
- 录屏合成逻辑。
- 自动进入练习页时的摄像头授权流程。

#### 4.1.1 隐藏摄像头但保留识别

CSS：

```css
#cameraVideo {
  opacity: 0;
  visibility: hidden;
  pointer-events: none;
}
```

关键点：

- 不能使用 `display: none`，否则浏览器可能停止视频绘制或影响 MediaPipe 读取。
- 不能停止 `srcObject`，否则评分链路中断。
- 舞台背景由 `.stage-media` 提供，不再依赖视频画面铺底。

#### 4.1.2 标准动作独立显示

原逻辑：

1. 绘制标准动作。
2. 绘制用户人体。
3. 绘制用户骨架 accent。
4. 绘制用户手部。

新逻辑：

1. 获取当前标准帧。
2. 如果当前帧没有有效 `pose_landmarks`，查找最近可渲染标准帧。
3. 将标准动作重投影到默认舞台参考系。
4. 绘制标准人体模型。
5. 绘制标准手部线条。
6. 用户姿态只参与评分，不进入 canvas 绘制。

新增函数：

- `getNearestRenderableFrame()`
- `refreshTeacherPalette()`
- `deriveTeacherPaletteFromClothing()`
- `drawOrganicLimb()`
- `drawJointOrb()`

#### 4.1.3 默认舞台参考系

标准动作不再贴合用户身体位置，否则用户不入镜或摄像头未授权时会出现视觉跳动。

默认参考系：

```js
{
  center: { x: 0.5, y: 0.5 },
  scale: 0.28,
  xAxis: { x: 1, y: 0 },
  yAxis: { x: 0, y: 1 },
}
```

后续如果需要"标准动作随用户位置轻微偏移"，可以引入可配置项，但默认应保持标准动作居中稳定。

### 4.2 新入口 `web/` 同步范围

文件：

- `web/src/main.ts`
- `web/src/app/canvasPainter.ts`
- `web/src/styles/practice.css`
- `web/src/app/canvasPainter.test.ts`

同步原则：

- `web/` 不能只做样式同步，必须同步渲染行为。
- 颜色算法放在 `canvasPainter.ts`，方便单元测试。
- `main.ts` 负责摄像头采样、teacher palette 状态、练习循环接线。
- `practice.css` 隐藏视频并提供舞台背景。

### 4.3 衣着主色提取与对比色算法

#### 4.3.1 采样区域

使用用户姿态关键点估算上半身衣着区域：

- 左肩 `11`
- 右肩 `12`
- 左髋 `23`
- 右髋 `24`

如果髋部关键点不可见，则使用肩宽估算 torso 高度。

采样区域需要做边界扩张：

- x 方向扩大 18%。
- y 方向扩大 12%。
- 宽高限制在合理范围，避免采到全背景。

#### 4.3.2 采样频率

建议间隔：`650ms`

原因：

- 不需要每帧计算主色，避免影响低端设备。
- 衣着颜色短时间内稳定，650ms 足够平滑。
- 颜色变化通过 `blendRgbColor()` 做 EMA 平滑，避免线条闪烁。

#### 4.3.3 主色聚类

采样 canvas：`48 x 48`

处理规则：

- 跳过透明度低的像素。
- 跳过过暗和过亮像素。
- 按 RGB 高 4 bit 建桶。
- 中心区域像素权重更高。
- 高饱和度和中等亮度像素权重更高。

#### 4.3.4 对比色生成

流程：

1. 将衣着主色 RGB 转 HSL。
2. 生成多个候选色相：`+180`、`+150`、`+210`、`+120`、`+240`。
3. 生成多档亮度：`0.58`、`0.66`、`0.74`。
4. 计算候选色与衣着主色、深色舞台背景的综合对比度。
5. 选择分数最高的颜色作为教师线条色。

对比目标：

- 与衣着主色形成明显区分。
- 与深色舞台背景保持足够亮度。
- 不让界面长期固定在单一黄色/青色方案。

### 4.4 人体动作模型优化

#### 4.4.1 当前问题

原骨架线条主要表现为直线段和圆点：

- 肢体像机械连杆。
- 躯干像平面四边形。
- 关节过渡生硬。
- 舞蹈动作缺少肌肉弧度。

#### 4.4.2 新模型结构

人体模型分成六类部件：

| 部件 | 实现方式 | 目标 |
| --- | --- | --- |
| 躯干 | 肩、腰、髋之间贝塞尔曲线 | 收腰、减少直板感 |
| 胸腹体块 | 胸腔、腰腹、骨盆三段叠加 | 接近 BJD 身体分件 |
| 四肢 | 双侧二次曲线轮廓 + 半径渐变 | 模拟肌肉走向和肢体发力 |
| 关节 | 关节球 | 借鉴 BJD 关节质感 |
| 手脚端点 | 圆形端点 | 保持端点辨识度 |
| 材质层 | 线性渐变、径向高光、暗部边缘 | 模拟树脂/塑料娃娃质感 |

#### 4.4.3 视觉规格

参考图的关键特征不是"线条更粗"，而是"可动娃娃分件"：

1. 身体被拆成独立部件，部件之间有清晰分割线。
2. 肩、肘、腕、髋、膝、踝都有圆形或椭圆形关节结构。
3. 肢体不是等宽胶囊，而是近端粗、远端细。
4. 躯干不是直板，胸腔、腰、骨盆有轻微收放。
5. 表面有一侧高光和一侧阴影，形成树脂体积感。
6. 整体颜色可以是浅树脂色，也可以用自动对比色作为描边/发光层。

建议采用"双层渲染"：

| 层 | 内容 | 作用 |
| --- | --- | --- |
| 实体层 | 树脂色人体体块 | 负责 BJD 娃娃观感 |
| 导师线层 | 高对比描边、关节环、手部线条 | 负责教学动作可读性 |

这样既能接近参考图，又不会因为纯浅色模型在复杂背景上看不清。

#### 4.4.4 关键点到部件映射

沿用 MediaPipe Pose 33 点，不修改 JSON schema。

| 部件 | 关键点 | 绘制策略 |
| --- | --- | --- |
| 头部 | `0`、`7`、`8`、肩中点 | 可选，当前可继续隐藏或画简化颈部 |
| 胸腔 | `11`、`12`、肩中点、腰点 | 曲线梯形/椭圆体块 |
| 腰腹 | 肩中点、髋中点 | 收腰曲线 |
| 骨盆 | `23`、`24`、髋中点 | 倒梯形/椭圆体块 |
| 左上臂 | `11 -> 13` | 近肩粗、近肘细 |
| 左前臂 | `13 -> 15` | 近肘粗、近腕细 |
| 右上臂 | `12 -> 14` | 近肩粗、近肘细 |
| 右前臂 | `14 -> 16` | 近肘粗、近腕细 |
| 左大腿 | `23 -> 25` | 近髋粗、近膝细 |
| 左小腿 | `25 -> 27` | 近膝粗、近踝细 |
| 右大腿 | `24 -> 26` | 近髋粗、近膝细 |
| 右小腿 | `26 -> 28` | 近膝粗、近踝细 |
| 手 | `15/16` + hand landmarks | 简化手掌或标准手部线条 |
| 脚 | `27/28/29/30/31/32` | 椭圆脚掌或简化圆端 |

#### 4.4.5 四肢曲线规则

每段肢体使用：

- 起点半径。
- 终点半径。
- 曲率参数。
- 高光方向。
- 关节端分割线。

示例：

```js
[11, 13, upperArmR * 1.08, upperArmR * 0.9, -0.035]
```

含义：

- 肩到肘。
- 肩端略粗，肘端略细。
- 轻微向一侧弯曲，避免直线机械感。

建议半径比例：

| 部件 | 起点半径 | 终点半径 | 备注 |
| --- | --- | --- | --- |
| 上臂 | `scale * 0.12` | `scale * 0.095` | 肩端饱满 |
| 前臂 | `scale * 0.095` | `scale * 0.07` | 腕端明显收细 |
| 大腿 | `scale * 0.15` | `scale * 0.11` | 髋端最粗 |
| 小腿 | `scale * 0.11` | `scale * 0.075` | 踝端收细 |

#### 4.4.6 关节分割线

参考图中 BJD 质感很大一部分来自部件接缝。2D Canvas 可以用弧线模拟：

- 肩关节：圆球外圈 + 半透明内弧。
- 肘关节：小圆球 + 横向弧线。
- 腕关节：小椭圆环。
- 髋关节：骨盆边缘的半圆接缝。
- 膝关节：膝盖圆球 + 上下两条短弧。
- 踝关节：小椭圆环。

绘制顺序：

1. 肢体暗部底色。
2. 肢体主色渐变。
3. 关节球。
4. 关节接缝线。
5. 高光。
6. 教师高对比描边。

#### 4.4.7 材质与光照

2D Canvas 版本不做真实光照，但必须模拟三种视觉信息：

| 信息 | Canvas 实现 | 参数建议 |
| --- | --- | --- |
| 主体树脂色 | `createLinearGradient()` | 暖白或动态肤色 |
| 暗部边缘 | 侧边半透明深色 stroke | alpha `0.18 - 0.32` |
| 高光 | 沿肢体方向画窄渐变曲线 | alpha `0.22 - 0.45` |

颜色建议：

- 默认实体色：`#f3eadc`、`#fff8ec`、`#d8c3a8`。
- 关节线：`rgba(90, 58, 42, 0.32)`。
- 高光：`rgba(255, 255, 255, 0.45)`。
- 教师描边：继续使用衣着互补色。

#### 4.4.8 2D Canvas 与 Three.js 路线选择

| 路线 | 适合阶段 | 优点 | 缺点 |
| --- | --- | --- | --- |
| Canvas 伪 3D | 当前 MVP | 不引入大依赖，能直接接现有关键点，性能可控 | 不能真实旋转，遮挡关系有限 |
| Three.js 分段模型 | 视觉升级阶段 | 最接近参考图，可做真实材质、光照、遮挡 | 需要建模、骨骼绑定、性能适配 |
| GLB BJD 模型 + 骨骼驱动 | 高保真阶段 | 可复用标准动画资产，观感最好 | 素材和绑定成本最高 |

推荐路线：

1. 先做 Canvas 伪 3D，达到 70% 的参考图观感。
2. 再封装 `TeacherAvatarRenderer`，让 Canvas 和 Three.js 可以替换。
3. 如果产品验证需要更强视觉，再引入 Three.js / GLB。

#### 4.4.9 Three.js 升级预案

如果后续需要真实 BJD 模型，建议新增独立模块，不直接塞进 `pose_viewer.html`。

建议文件：

- `web/src/app/teacherAvatar/TeacherAvatarRenderer.ts`
- `web/src/app/teacherAvatar/CanvasTeacherAvatar.ts`
- `web/src/app/teacherAvatar/ThreeTeacherAvatar.ts`
- `web/src/app/teacherAvatar/poseToRig.ts`

Three.js 方案关键步骤：

1. 准备一个分件 BJD `.glb` 模型。
2. 模型对象分为 torso、pelvis、upperArm、forearm、thigh、calf、hand、foot。
3. 每个对象的 pivot 放在近端关节点，例如上臂 pivot 在肩。
4. 根据 `a -> b` 关键点方向计算 2D/3D 旋转。
5. 用肩宽和髋宽计算整体 scale。
6. 用 Z 轴或绘制顺序处理前后遮挡。
7. 使用浅树脂材质、环境光、轮廓光和接触阴影。

最低可接受 Three.js 效果：

- 标准动作能跟随 JSON 播放。
- 上肢和下肢方向与关键点一致。
- 关节位置不明显脱节。
- 移动端保持 30 FPS 以上。

### 4.5 录屏与 Remotion 预留

当前录屏模块继续使用浏览器 `MediaRecorder`，但合成画面应改为：

1. 绘制标准舞台背景。
2. 绘制 `overlayCanvas`。
3. 合成 BGM 音轨。

不再把 `#cameraVideo` 画进录屏。

Remotion 后续可作为增强项：

- 生成"标准动作单独展示"宣传短片。
- 生成"练习结果复盘"视频模板。
- 生成对外评审用的前后对比 demo。

本阶段不新增 Remotion 代码，避免扩大改动面。

## 5. 分阶段实施计划

### Phase 1：视觉层拆分

目标：做到"用户看不到自己，但评分不断"。

任务：

- 隐藏 `#cameraVideo`。
- 修改 `.stage-media` 背景。
- 从 canvas 渲染路径移除用户人体、用户骨架、用户手部。
- 保留 `state.lastPose`、`state.lastHands`、`safeRefreshMatchScore()`。
- 保留 HUD、结果页结算和节拍反馈。

验收：

- 练习页无用户视频画面。
- 练习页无用户骨架。
- 未开摄像头时仍可观看标准动作。
- 开摄像头后能继续产生分数。

### Phase 2：标准动作模型升级

目标：让标准动作不再是机械骨架。

Phase 2 拆成三个可独立验收的小阶段。

#### Phase 2A：Canvas 伪 3D 体块

任务：

- 躯干从四点多边形改为曲线轮廓。
- 四肢从直胶囊升级为曲线轮廓。
- 肩、肘、髋、膝增加关节球。
- 手脚端点保留圆形端点。
- 旧入口和 `web/` 入口保持一致。

验收：

- 标准动作中心稳定。
- 动作轮廓有身体厚度和关节层次。
- 低可见度关键点不会绘制异常大块。
- 第一批空 pose 帧不会导致舞台空白。

#### Phase 2B：BJD 接缝与材质

任务：

- 给肩、肘、腕、髋、膝、踝增加分割弧线。
- 给四肢增加沿肢体方向的高光。
- 给体块增加侧边暗部。
- 调整绘制顺序，避免关节球被肢体盖住。
- 增加浅树脂色默认主题，同时保留动态对比描边。

验收：

- 静止帧看起来像分件人偶，而不是普通粗线条。
- 肘、膝、髋关节有明确接缝。
- 高光不会盖住教学描边。
- 低分辨率移动端仍能看清动作方向。

#### Phase 2C：封装渲染器

任务：

- 抽出 `drawTeacherAvatar()` 或 `TeacherAvatarRenderer`。
- 输入只依赖 `pose_landmarks`、`hands`、`palette`、`stageRect`。
- 输出只负责 canvas 绘制，不读全局状态。
- 旧入口保留轻量适配层，新入口使用模块化实现。

验收：

- 旧入口和 `web/` 不再各自复制大量绘制逻辑。
- 可单独测试颜色、半径、关键点映射等纯函数。
- 后续 Three.js 版本可以在同一接口下替换。

### Phase 3：动态高对比色

目标：标准动作线条能根据用户衣着自动避让颜色。

任务：

- 从摄像头帧采样上半身衣着区域。
- 计算主色。
- 根据 HSL 候选色生成高对比教师色。
- 平滑颜色变化。
- 在标准人体和标准手部上统一使用教师色。
- 给颜色算法补单元测试。

验收：

- 红色衣着时，教师线条偏青蓝或同等高对比色。
- 蓝色衣着时，教师线条偏暖色或同等高对比色。
- 与深色舞台背景对比度足够。
- 颜色不会高频闪烁。

## 7. 风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 摄像头隐藏后浏览器停止视频帧 | MediaPipe 不再收到画面 | 使用 `opacity: 0` 和 `visibility: hidden`，不使用 `display: none` |
| 自动摄像头授权阻塞进入练习页 | 用户一直停留准备页 | 先进入练习页，再异步请求摄像头 |
| 部分动作前几帧没有 pose | 练习页短暂空白 | `getNearestRenderableFrame()` 查找最近有效帧 |
| 颜色采样采到背景 | 教师颜色不理想 | 采样区域基于肩髋关键点，中心加权，跳过极暗/极亮像素 |
| 颜色频繁变化 | 线条闪烁 | 限制采样频率，并对 RGB 做平滑 |
| 曲线人体遮挡过多 | 动作细节不清 | 降低 fill alpha，保留清晰 stroke 和 accent |
| BJD 体块过度拟真 | 分散教学注意力 | 实体层透明度保持克制，高对比导师线层优先 |
| 接缝线太多 | 小屏幕显脏 | 移动端只保留肘、膝、髋核心接缝 |
| 关键点低置信度 | 肢体乱跳或断裂 | 每段肢体独立检查 visibility，不满足阈值则跳过 |
| 左右肢体交叉 | 遮挡顺序不真实 | Canvas 阶段用固定层级兜底，Three.js 阶段再做真实深度 |
| Three.js 过早引入 | 增加包体和适配成本 | 当前阶段只做 Canvas，可替换接口先行 |
| 新旧入口行为分叉 | 迁移后体验不一致 | `pose_viewer.html` 和 `web/` 同步改动，同步测试 |

## 10. BJD 效果任务拆分

### 10.1 第一批：立刻可做

目标：不用新增依赖，在当前 Canvas 中做出接近参考图的基础效果。

任务：

1. 给 `drawHumanBody()` 增加材质参数：`resinFill`、`shadowColor`、`highlightColor`、`jointStroke`。
2. 把躯干拆成胸腔、腰腹、骨盆三个曲线体块。
3. 把四肢绘制从单一填充改为主渐变 + 边缘暗部 + 高光线。
4. 增加 `drawJointSeam()`，绘制肘、膝、髋的接缝弧线。
5. 增加移动端降级：小屏幕或低 FPS 时关闭高光，只保留体块和接缝。

交付物：

- 标准动作舞台截图。
- 红/蓝/黑/白衣着模拟截图。
- 移动端 390x844 截图。
- `npm run web:test` 和 `npm run web:build` 结果。

### 10.2 第二批：模块化

目标：避免 `pose_viewer.html` 和 `web/` 双份绘制逻辑继续膨胀。

任务：

1. 在 `web/src/app/teacherAvatar/` 新增模块化 Canvas 渲染器。
2. 把纯函数迁入 `web/`，旧入口只保留兼容版本或引用构建产物。
3. 增加 `poseParts.ts`，集中维护关键点映射和半径比例。
4. 增加测试覆盖：空帧、低置信度、左右肢体、半身动作。

交付物：

- 独立 teacher avatar 模块。
- 单元测试。
- 与旧入口显示一致的截图对比。

### 10.3 第三批：Three.js 可行性验证

目标：判断是否值得投入真实 3D BJD 模型。

任务：

1. 找一个可商用或自制的分件 BJD `.glb`。
2. 做一个最小 demo，只驱动上臂、前臂、大腿、小腿。
3. 对比 Canvas 版本和 Three.js 版本在移动端的 FPS、加载时间、视觉提升。
4. 决定是否进入正式 Three.js 方案。

进入条件：

- Canvas 版本已经无法满足视觉要求。
- 产品侧明确需要接近参考图的真实 3D 质感。
- 移动端性能测试达到最低 30 FPS。

## 11. 推荐落地顺序

1. 先完成旧入口 `pose_viewer.html`，因为它是当前主体验。
2. 同步 `web/` 入口，避免 Phase 1/2 迁移返工。
3. 做 Canvas BJD 第一批效果：体块、关节、接缝、高光。
4. 补齐颜色算法和 teacher avatar 纯函数测试。
5. 跑构建、单测、截图验证。
6. 如可用，跑 CodeRabbit 未提交变更审查。
7. 再考虑 Remotion 或更完整的视频模板化输出。
8. 最后评估 Three.js / GLB 是否值得引入。
